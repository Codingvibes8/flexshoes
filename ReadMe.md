# FlexShoes - Premium Online Shoe Store

A stunning, modern e-commerce website for FlexShoes,
featuring an elegant design with vibrant colors,
smooth animations, 
and a comprehensive shopping experience.

## 🛠️ Installation & Setup

1. **Clone the repository**
   ```bash
   git clone <repository-url>
   cd flexshoes
   ```

2. **Install dependencies**
   ```bash
   npm install
   ```

3. **Configure environment variables**

   Copy `.env.example` to `.env.local` and fill in:
   - `DATABASE_URL` - your Neon Postgres connection string
   - `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY` and `CLERK_SECRET_KEY` - from the Clerk dashboard

   For local development you can skip creating a Clerk account:

   ```bash
   npx clerk@latest init --accountless
   ```

   That writes temporary development keys to `.env.local`. Claim the app later
   with `npx clerk auth login`, or replace the keys with your own from
   [dashboard.clerk.com](https://dashboard.clerk.com/~/api-keys).

4. **Apply the database schema and seed demo data**
   ```bash
   npm run db:migrate
   npm run db:seed
   ```

5. **Run the development server**
   ```bash
   npm run dev
   ```

6. **Open your browser**
   Navigate to [http://localhost:3000](http://localhost:3000)

## 🗄️ Database

The database lives in Neon and is accessed through Drizzle ORM.

- Schema: `lib/db/schema.ts`
- Client: `lib/db/index.ts` (Neon HTTP driver)
- Queries: `lib/db/helpers.ts`
- Migrations: `drizzle/` (generated by Drizzle Kit)

| Command | Description |
| --- | --- |
| `npm run db:generate` | Generate a SQL migration from the schema |
| `npm run db:migrate` | Apply pending migrations to Neon |
| `npm run db:push` | Push the schema directly (prototyping) |
| `npm run db:studio` | Open Drizzle Studio |
| `npm run db:seed` | Seed categories and demo products |

## 🔐 Authentication

Clerk handles sign-up, sign-in, sessions, and user records. There is no local
users table; orders store the Clerk `userId`.

- `middleware.ts` runs `clerkMiddleware()` for every request
- `app/layout.tsx` wraps the app in `ClerkProvider`
- `app/sign-in` and `app/sign-up` render Clerk's prebuilt forms
- `app/account` is a protected server component
- `lib/auth/helpers.ts` exposes `authHelpers` for server code

To protect a server action or route handler:

```ts
import { auth } from "@clerk/nextjs/server"

const { userId } = await auth()
if (!userId) throw new Error("Unauthorized")
```

## 🚀 Deployment

This project is optimized for deployment on Vercel:

1. **Push to GitHub**
2. **Create a Neon project** and copy its pooled `DATABASE_URL`
3. **Import the repo into Vercel** and add these environment variables:
   - `DATABASE_URL`
   - `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY`
   - `CLERK_SECRET_KEY`
   - `NEXT_PUBLIC_CLERK_SIGN_IN_URL=/sign-in`
   - `NEXT_PUBLIC_CLERK_SIGN_UP_URL=/sign-up`
   - `NEXT_PUBLIC_CLERK_SIGN_IN_FALLBACK_REDIRECT_URL=/`
   - `NEXT_PUBLIC_CLERK_SIGN_UP_FALLBACK_REDIRECT_URL=/`
4. **Apply migrations** with `npm run db:migrate` (and optionally `npm run db:seed`)
5. **Deploy**

## 🔧 Customization

### Adding New Products
Products live in Neon. Use either:

- **Drizzle Studio**: run `npm run db:studio` and edit rows in the UI
- **SQL/Drizzle**: insert into the `products` table using `lib/db/helpers.ts`
  patterns as a reference

The `lib/products.ts` catalog is only used by `npm run db:seed` to populate an
empty database. Product images can be local files in `public/` or HTTPS URLs.

### Changing the Database Schema
1. Edit `lib/db/schema.ts`
2. Run `npm run db:generate` to create a migration
3. Run `npm run db:migrate` to apply it

### Styling Changes
- Global styles: `app/globals.css`
- Component styles: Individual component files
- Design tokens: CSS custom properties in globals.css
